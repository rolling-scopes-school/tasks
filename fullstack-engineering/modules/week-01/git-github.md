# Знакомство с системой контроля версий Git и веб-сервисом GitHub

## Цели модуля

1. Получить общее представление о системе контроля версий Git.
2. Начать работать с Git с использованием веб-сервиса GitHub.
3. Познакомиться со следующими понятиями:
   - репозиторий: локальный (`local`) и удалённый (`remote/origin`);
   - рабочая директория (`working directory`);
   - область подготовленных файлов (`staging area`).

4. Изучить основные команды Git: `clone`, `add`, `commit`, `push`, `pull`.
5. Познакомиться с понятием ветки (`branch`) в Git: созданием веток, слиянием (`merge`) и перебазированием (`rebase`).
6. Познакомиться с основами Markdown и создать страницу с использованием этого языка разметки.
7. Создать и опубликовать собственную веб-страницу с помощью GitHub Pages.

## Приблизительное время прохождения модуля

Теория: 3 часа
Практика: 4 часа

## Теория

1. Прочитайте и запомните [требования RS School к оформлению коммитов](https://rs.school/docs/git-convention).
2. Посмотрите видеоматериал [«Теория Git/GitHub»](https://www.youtube.com/watch?v=SWYqp7iY_Tc) — около 30 минут.
3. Посмотрите видео [Git Workshop на русском языке](https://youtu.be/Dlr_E7WfA08) и параллельно попробуйте самостоятельно выполнить показанные действия в Git — 30 минут.
4. Изучите [документацию по Markdown](https://guides.github.com/features/mastering-markdown/). Сначала можно познакомиться с основными возможностями и синтаксисом, а затем подробнее изучать их во время практики — 30 минут.
5. Изучите краткую инструкцию MDN по [настройке GitHub Pages в репозитории](https://developer.mozilla.org/en-US/docs/Learn/Common_questions/Tools_and_setup/Using_GitHub_pages) и [официальную документацию GitHub Pages](https://pages.github.com/).
6. Посмотрите видеоинструкцию [по публикации страницы с помощью GitHub Pages](https://www.youtube.com/watch?v=OltY8JIaP-4) — 7 минут.

## Практика

1. Пройдите тест `[St1] Git test` в разделе `Auto-Test` платформы RS APP.
2. Используйте [интерактивный тренажёр](https://learngitbranching.js.org/), чтобы попрактиковаться в работе с Git.
