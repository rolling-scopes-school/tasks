# Country Search

## Навыки

`JavaScript` `TypeScript` `fetch` `Promise` `async/await` `AbortController` `debounce` `обработка ошибок` `TDD` `FIRST` `Jest/Vitest` `ESLint` `Prettier` `Husky`

## Что делать

Живой поиск стран по имени через публичный [REST Countries API](https://restcountries.com) (`GET https://restcountries.com/v3.1/name/{query}`, без ключа, с поддержкой CORS). Пользователь печатает — приложение само, по мере ввода, посылает запросы и показывает результаты.

Задача не про верстку списка карточек — она у вас уже получалась. Задача про частый баг прода: **гонку устаревших ответов**. Если при вводе `sp` сервер отвечает медленнее, чем при вводе следующего `spain`, то ответ на `sp` может прилететь позже и перезаписать на экране уже правильный результат по `spain` более старым. Без явной отмены предыдущего запроса эта гонка — вопрос времени, а не "если".

Решать её нужно по-настоящему: `AbortController`, а не "просто игнорировать пришедший позже ответ флагом". При этом нужно аккуратно не спутать два случая в `catch`:

- запрос отменён вами самими (новый ввод/очистка поля) — это не ошибка, пользователю ничего показывать не нужно;
- запрос действительно упал (сеть, сервер, таймаут) — это ошибка, и её нужно показать с возможностью повторить.

### Обязательная логика (проверяется явно)

- **`debounce(fn, delay)`** — функция высшего порядка, которая задерживает вызов `fn` на `delay` мс, если за это время её позвали снова — таймер сбрасывается. Реализуйте сами, без lodash/подобных библиотек.
- **`searchCountries(query, signal)`** — обёртка над `fetch`: принимает строку поиска и `AbortSignal`, возвращает промис с массивом стран. Обязательно проверяет `response.ok` — `fetch` **не бросает исключение** на HTTP-ошибках (4xx/5xx), это нужно проверять руками.
- **`HttpError`** — свой класс ошибки (`extends Error`), хранит статус ответа. Бросается из `searchCountries`, когда `response.ok === false` и статус не означает "совпадений нет" (см. ниже).
- **Семантика 404**: REST Countries отвечает `404`, когда совпадений нет — это **не ошибка**, а пустой результат. Любой другой неуспешный статус (500, таймаут, обрыв сети) — настоящая ошибка, которую нужно показать пользователю с кнопкой повтора.
- **`mapCountryResponse(raw)`** — чистая функция, преобразующая ответ API в данные для карточки (название, флаг, столица, регион, население, языки). Тестируется без сети, на заготовленных JSON-примерах.
- **Отмена**: при каждом новом запросе предыдущий **в самом деле отменяется** через `AbortController.abort()`, а не просто игнорируется. Ошибка отмены (`AbortError`) в `catch` не должна попадать в ветку показа ошибки пользователю.

### Экран и состояния

- Поле ввода. Пустой ввод — запрос не отправляется, список очищается.
- Пока запрос летит — индикатор загрузки.
- Результаты — список карточек (флаг, название, столица, регион, население).
- Нет совпадений (404) — дружелюбное "ничего не найдено", не похожее на ошибку.
- Настоящая ошибка (не 404) — сообщение об ошибке и кнопка "Повторить", которая повторяет именно последний введённый запрос.
- Клик по карточке — детальный вид страны (языки, площадь, соседи и что сочтёте нужным из ответа API).

### Бонус (не входит в обязательный объём, даёт баллы сверху)

- Кэш ответов по строке запроса: повторный одинаковый запрос (например, пользователь стёр и напечатал то же самое) берётся из кэша, а не уходит в сеть снова. Если на момент повторного запроса с тем же текстом уже есть **в полёте** такой же запрос — не плодить второй, использовать тот же промис.
- История последних запросов (localStorage), клик по пункту истории — мгновенный повторный поиск (из кэша, если он есть).

## Требования

### Настройка проекта

- TypeScript обязателен для всей логики и UI.
- ESLint, Prettier, Husky + lint-staged настроены и работают.
- `package.json` содержит скрипты `lint`, `format`, `test`.
- Бандлер не обязателен (его будете проходить на неделе 11–12) — компилируйте через `tsc` в ES-модули, подключайте в `index.html` через `<script type="module">`.
- Тестовый раннер — Jest или Vitest, с поддержкой fake timers и мокированием `fetch`.

### TDD и порядок коммитов

Для каждой из обязательных функций (`debounce`, `searchCountries`, `mapCountryResponse`, логика различения `AbortError`/`HttpError`/404):

1. Отдельный коммит с падающими тестами, написанными по **FIRST**, раньше реализации.
2. Отдельный коммит с реализацией, после которого тесты зелёные.

Отдельно, своим коммитом (после того как базовая логика покрыта) — тест на саму гонку: мок `fetch`, где промис по более раннему запросу резолвится **после** промиса по более позднему, и проверка, что в итоговом состоянии приложения результат соответствует только последнему запросу.

### Архитектура

- `body` в `index.html` пустой (кроме `<script>`).
- Вся логика запроса/отмены/маппинга/дебаунса не зависит от DOM и тестируется без браузера и без реальной сети (сеть мокируется в тестах).
- Никакого `innerHTML`/`insertAdjacentHTML` для динамического контента.

### Документация — `DESIGN.md`

Отдельный файл в корне репозитория:

1. Как устроена отмена устаревших запросов и почему именно так (а не, например, просто флагом "актуальный ли это ответ").
2. Обоснование выбранной задержки `debounce` — что будет, если её убрать или сильно увеличить.
3. Сложность (Big O) для `mapCountryResponse` и, если делали бонус, для кэша/дедупликации запросов.
4. Какие принципы чистого кода применены и где конкретно (файл/функция).

## Чего делать не нужно

- Не использовать сторонние библиотеки для debounce/кэширования (lodash и подобные) — цель задания написать это руками.
- Не маскировать гонку запросов костылём вида "показывать только самый последний полученный ответ по таймстампу" без реальной отмены через `AbortController` — задание именно про отмену, а не про фильтрацию результатов постфактум.
- Не писать свой backend/прокси для API — REST Countries поддерживает CORS напрямую из браузера.
- Не писать реализацию раньше тестов для функций из обязательного списка — порядок коммитов проверяется.
