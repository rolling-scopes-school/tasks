# Landing Page. Часть 2: Функциональность

Продолжение [Части 1](README-part-1.md) — добавьте интерактивность и работу с браузерными хранилищами к странице, свёрстанной ранее.

## Что делать

1. Продолжите работу в ветке `landing-page-part-2`, созданной от `landing-page`.
2. Добавьте JS-интерактивность к секциям и элементам, размеченным в Части 1.
3. Реализуйте переключение темы и историю заявок, как описано в требованиях ниже.

## Требования

### Интерактивность

- Бургер-меню открывается/закрывается по клику, закрывается по клику на пункт меню/оверлей.
- Слайдер/карусель работает от кнопок вперёд/назад (свайп — по желанию); реализация полностью своя, без готовых библиотек.
- Модальное окно открывается/закрывается (кнопка закрытия, клик по оверлею, `Esc`).
- Форма валидируется на клиенте: обязательные поля, понятные сообщения об ошибках, невозможность отправить некорректные данные.

### Переключение темы + localStorage (обязательно)

- Кнопка/иконка переключения темы, добавленная в header в Части 1, должна реально переключать светлую/тёмную тему оформления страницы.
- Выбранная тема сохраняется в `localStorage` и применяется при повторном открытии страницы.

### История заявок + IndexedDB (обязательно)

- При успешной отправке формы запись (введённые поля + дата/время) сохраняется в IndexedDB, а не только "исчезает" после отправки.
- На странице есть блок/модалка «Ваши заявки» (название — на ваше усмотрение по теме), который при загрузке страницы читает и показывает все ранее сохранённые в IndexedDB записи.
- Разница между хранилищами должна быть логичной, а не формальной: `localStorage` — простое хранение состояния интерфейса (тема), `IndexedDB` — хранение коллекции структурированных записей (заявки).

### Технические требования

- Все технические требования Части 1 остаются в силе.
- Используется нативный `IndexedDB` API — сторонние библиотеки-обёртки (`idb`, `dexie`, `localforage` и т.п.) не допускаются; можно написать свои небольшие промис-хелперы.
- Использование готовых библиотек для слайдера/модалки/валидации (Swiper, SweetAlert и т.п.) не допускается.
- jQuery и другие устаревшие библиотеки не допускаются.
- JS-фреймворки (React, Vue, Angular и т.п.) не допускаются.
- TypeScript не допускается.

Задание проверяется через [cross-check](https://rs.school/docs/cross-check-flow). Проверяется вся реализованная функциональность, включая корректную работу переключения темы и истории заявок после перезагрузки страницы.

## Критерии оценки

**Максимальный балл: 100**

Сумма баллов по всем пунктам больше 100 — это специально сделанный запас, который сглаживает неточности проверки и разное понимание требований. Итоговый балл всё равно ограничен сверху 100.

1. Бургер-меню открывается/закрывается по клику; закрывается по клику на пункт меню или на оверлей: **+10**
2. Слайдер/карусель переключает карточки по кнопкам вперёд/назад, реализован без готовых библиотек: **+10**
3. Модальное окно открывается по клику на карточку, закрывается по кнопке закрытия, клику на оверлей и по `Esc`: **+10**
4. Форма валидируется на клиенте: обязательные поля проверяются, при ошибке показывается понятное сообщение, отправить некорректные данные невозможно: **+10**
5. Кнопка переключения темы реально меняет оформление страницы (светлая/тёмная): **+10**
6. Выбранная тема сохраняется в `localStorage` и применяется при повторном открытии страницы: **+10**
7. При успешной отправке формы запись (поля формы + дата/время) сохраняется в IndexedDB: **+15**
8. Блок «Ваши заявки» при загрузке страницы читает и отображает все ранее сохранённые в IndexedDB записи: **+15**
9. После перезагрузки страницы тема и список заявок остаются прежними — сохранённое состояние переживает reload: **+10**
10. Используется нативный `IndexedDB` API без сторонних библиотек-обёрток (`idb`, `dexie`, `localforage` и т.п.): **+5**
11. В консоли DevTools нет ошибок при обычном использовании страницы (открытие, отправка формы, переключение темы, работа слайдера/модалки): **+5**

### Штрафы

- Использование запрещённых технологий (JS-фреймворки, TypeScript, готовые библиотеки для слайдера/модалки/валидации, сторонние обёртки для IndexedDB и т.п.): **-100**
- Переключение темы или история заявок реализованы «для вида», без реального сохранения в localStorage/IndexedDB: **-100**
