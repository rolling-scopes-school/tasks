# Landing Page

## Описание проекта

Landing Page — задание, в котором нужно создать одностраничный сайт (лендинг) на тему по своему выбору: сначала сверстать адаптивную страницу по дизайну, затем добавить интерактивность и работу с браузерными хранилищами данных.

В отличие от заданий, где все делают вёрстку по одному и тому же макету, здесь у вас есть творческая свобода: вы сами придумываете тему лендинга (или берёте одну из примеров ниже) и с помощью Figma AI создаёте по обезличенному шаблону собственный уникальный дизайн. Перед стартом задания пройдёт стрим, на котором покажут, как пользоваться Figma AI для этого.

При этом часть требований жёстко зафиксирована и одинакова для всех — шапка и подвал сайта, минимальный набор секций и функциональности. Это даёт свободу в содержании и креативе, но сохраняет единые технические критерии проверки.

## Навыки

`HTML` `CSS` `Figma` `Figma AI` `JavaScript` `DOM` `localStorage` `IndexedDB`

## Из чего состоит задание

Задание разбито на две части, каждая длится одну неделю и оценивается через отдельный cross-check:

- **Часть 1. Вёрстка** — этот файл: выбор темы, дизайн в Figma AI по шаблону, адаптивная семантическая вёрстка.
- [Часть 2. Функциональность](README-part-2.md) — интерактивность (бургер-меню, слайдер, модалка, валидация формы, переключение темы) + сохранение данных в localStorage и IndexedDB.

## Выбор темы лендинга

Тему можно придумать полностью самостоятельно. Если пока нет идеи, можно взять один из примеров:

- кофейня / кафе
- спортзал / фитнес-студия
- языковые курсы
- стоматология / клиника
- барбершоп
- бьюти-салон
- IT-курс / буткемп
- SaaS-продукт / стартап
- музыкальная группа
- благотворительное событие
- доставка еды
- автосервис
- приют для животных

Тема должна допускать естественное появление всех обязательных блоков задания: карточек для слайдера/карусели (услуги, меню, отзывы, портфолио и т.п.), формы заявки/записи/обратной связи и модального окна. Если тема настолько специфична, что это невозможно, лучше выбрать другую.

## Обязательные header и footer (общие для обеих частей)

Независимо от темы и дизайна, во всех работах должны быть одинаковые по структуре шапка и подвал — именно они проверяются с точностью до пикселя.

### Header

- Логотип/название лендинга — текстом или инлайн-SVG, не скриншотом.
- Навигация: список (`nav > ul > li > a`) с якорными ссылками на все основные секции страницы.
- Кнопка/иконка переключения светлой/тёмной темы (разметка — в Части 1, реальное переключение и сохранение выбора — в Части 2).
- Бургер-меню для мобильной версии (разметка — в Части 1, поведение — в Части 2).

### Footer

- Логотип/название лендинга.
- Копирайт с годом создания сайта.
- Ссылка на курс RS School.

## Требования к Части 1: Вёрстка

### Что делать

1. Выберите тему лендинга — самостоятельно или из примеров выше.
2. Создайте свою копию обезличенного Figma-шаблона и с помощью Figma AI сгенерируйте дизайн под свою тему. Обязательно посмотрите стрим перед началом работы.
3. Доработайте сгенерированный дизайн вручную там, где нужно — Figma AI не обязан сразу дать пиксель-перфектный и логичный результат.
4. Сверстайте адаптивную страницу по получившемуся макету.

### Минимальный набор секций

- Не менее 4 контентных секций, не считая header и footer.
- Секция с карточками (не менее 8 штук) — в Части 2 станет слайдером/каруселью.
- Модальное окно, которое открывается по клику на карточку из этой секции и показывает дополнительную информацию о ней (например, развёрнутое описание, более крупное фото, детали услуги) — по умолчанию скрыто.
- Секция с формой заявки/записи/бронирования (конкретный смысл — под вашу тему): минимум поля — имя, способ связи (телефон или email), комментарий. В Части 2 данные успешной отправки будут сохраняться в IndexedDB.

### Технические требования

- Вёрстка валидная, семантическая, соответствует получившемуся макету.
- Корректно отображается в последней версии Google Chrome.
- Соответствие макету проверяется на ширине экрана 1440px, 768px и 380px (выбор промежуточных брейкпоинтов — на ваше усмотрение). На всех промежуточных ширинах между 1440px и 380px: нет горизонтального скролла, вёрстка адаптивна, весь контент сохранён, пропорции изображений не искажены.
- Использование HTML-препроцессоров и шаблонизаторов (Pug и т.п.) не допускается.
- Использование CSS-фреймворков (Bootstrap и т.п.) не допускается.
- CSS-препроцессоры (SASS/SCSS) и [modern-normalize](https://github.com/sindresorhus/modern-normalize) допускаются.
- TypeScript не допускается.
- Использование готовых JS-библиотек для слайдеров/модалок (Swiper и т.п.) не допускается — в Части 2 всё пишется самостоятельно.
- Секции/картинки не должны быть вставлены скриншотом макета — только тегами и реальными изображениями (фото/иконки).
- Код читаемый, без минификации; при использовании сборщика (Vite/Webpack) — с включёнными source maps.

## Требования к репозиторию

- Задание выполняется в личном публичном репозитории `rsschool-landing-page`.
- Ветка `main` должна оставаться пустой (только `README.md`, `.gitignore` и т.п.).
- Часть 1 выполняется в ветке `landing-page`, созданной от `main`.
- Часть 2 выполняется в ветке `landing-page-part-2`, созданной от `landing-page` (см. [README-part-2.md](README-part-2.md)).
- Внутренняя структура проекта — на ваше усмотрение.

## Как сдавать Часть 1

- Работа ведётся в ветке `landing-page`.
- Задеплойте страницу (например, через GitHub Pages).
- Откройте Pull Request из `landing-page` в `main`, не мержите его.
- Отправьте ссылку на этот Pull Request на cross-check.

## Cross-check

Задание проверяется через [cross-check](https://rs.school/docs/cross-check-flow). Проверяется валидность вёрстки, соответствие макету на ширине 1440px, 768px и 380px, адаптивность на промежуточных ширинах, отсутствие горизонтального скролла.

## Критерии оценки

**Максимальный балл: 100**

Сумма баллов по всем пунктам больше 100 — это специально сделанный запас, который сглаживает неточности проверки и разное понимание требований. Итоговый балл всё равно ограничен сверху 100.

1. Header и footer реализованы pixel perfect (в header: лого, nav, кнопка темы, разметка бургер-меню; в footer: лого, копирайт с годом создания, ссылка на курс) на ширине 1440px, 768px и 380px; допустимое отклонение — до 10px по горизонтали и вертикали при сохранении визуального сходства: **+10**
2. Навигация в header построена как `nav > ul > li > a`: **+5**
3. Остальные секции визуально соответствуют получившемуся у вас макету (не pixel perfect — оценивается сходство: расположение блоков, отступы, шрифты, цвета) на ширине 1440px, 768px и 380px. Чтобы проверяющий мог сравнить вёрстку с макетом, добавьте в Pull Request публичную ссылку на сгенерированный и использованный вами Figma-макет (проверьте, что она открывается в режиме инкогнито): **+10**
4. Не менее 4 контентных секций, не считая header и footer: **+5**
5. Секция с карточками (не менее 8 штук): **+10**
6. Модальное окно открывается по клику на карточку и по умолчанию скрыто в разметке: **+10**
7. Секция с формой заявки/записи/бронирования с нужными полями (имя, способ связи, комментарий): **+10**
8. На всех промежуточных ширинах между 1440px и 380px отсутствует горизонтальный скролл, вёрстка адаптивна, весь контент сохранён: **+10**
9. Вёрстка валидна по [W3C Validator](https://validator.w3.org/): **+10**
10. Семантическая вёрстка: теги `header`, `main`, `footer`, `section`, один `h1` на странице: **+5**
11. На странице есть `favicon`: **+5**
12. У всех значимых `<img>` заполнен осмысленный `alt`: **+5**
13. Кнопки, ссылки и карточки интерактивны (hover/focus): плавный переход стилей (transition), не влияющий на соседние элементы: **+5**
14. Плавная прокрутка по якорным ссылкам навигации: **+5**
15. Lighthouse Performance (DevTools, мобильный режим) не ниже 70: **+5**

### Штрафы

- Секции или картинки вставлены скриншотом макета вместо вёрстки тегами: **-100**
